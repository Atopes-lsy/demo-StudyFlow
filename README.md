# StudyFlow - HarmonyOS AI 学习规划助手

StudyFlow 面向学生的作业安排与考试复习场景，计划通过“任务管理 + 学习记录 + 用户自带模型 API Key + AI 计划校验”构建一个可执行的学习规划流程。

## 当前状态

截至 2026-10-08，本目录已有 ArkTS / ArkUI、Stage 模型的 HarmonyOS 工程，`entry` 首页仍为 Hello World 模板。下文的业务功能为待实现计划，尚未验证构建、真机运行、模型调用或 MCP 接入。

| 项目 | 状态 |
| --- | --- |
| 工程、GitHub 仓库和远程协作分支 | 已建立 |
| 本地任务、学习记录和首页统计 | 待实现 |
| 自带 API Key、模型设置和 AI 草稿 | 待实现 |
| 计划规则校验和业务测试 | 待实现 |
| MCP 两个只读工具 | 可选，基础验收后评估 |

## 首期功能

- 首页：今日任务、完成情况、学习时长及功能入口。
- 任务管理：新增、编辑、删除、筛选、完成状态和重启恢复。
- 学习记录：填写学习时长、备注和查看历史。
- 模型设置：模型服务、Base URL、模型 ID、遮蔽的 API Key 输入和连接检查。
- AI 规划：根据学习目标、每日预算及必要任务摘要生成可编辑草稿。
- 可信保存：程序校验字段、日期、时长和每日预算，用户确认后才保存；重复确认不重复入库。

主流程：

```text
配置自己的模型 -> 输入目标 -> 确认发送必要上下文
-> 生成草稿 -> 校验 -> 编辑后再次校验 -> 用户确认 -> 保存任务
```

未配置模型或模型不可用时，普通任务和记录功能仍须可用。API Key 首期只在应用进程内保留，不明文落盘、不进入日志、不经过小组中转服务器。真实模型调用可能产生用户账号费用，默认不自动重试。

## 三人分工

| 成员 | 负责范围 | 主要交付 |
| --- | --- | --- |
| 组长 | 模块契约、计划校验器、核心测试及关键集成评审 | 共享类型、校验逻辑、固定测试集、架构说明 |
| 组员 1 | 工程导航、首页、任务、学习记录、本地仓库与批量保存 | 业务页面、持久化、防重复保存、模块测试与截图 |
| 组员 2 | 模型设置、会话密钥、服务适配、AI 草稿交互与异常处理 | 模型接入、AI 页面、凭据及网络测试与截图 |

每人维护自己的测试与报告段落；组长不包办常规页面、存储、模型联网或全部文档。可使用 AI 辅助开发，但负责人必须验证并能解释自己的实现。

## 运行与环境

1. 克隆仓库，在 DevEco Studio 打开仓库根目录，不要再嵌套创建一个工程。
2. 按工程配置安装 SDK 并完成依赖同步。目前 `build-profile.json5` 的目标 SDK 为 `26.0.0`，兼容版本为 `6.1.1(24)`，以实际文件为准。
3. 选择 `entry` 和兼容的 Phone 模拟器或真机。签名配置尚为空，需要按本机环境配置后再尝试运行。
4. 当前应先验证模板页面；业务流程需实现后再测试。网络权限、模型服务兼容性和构建成功均不能仅凭模板推定。

`local.properties`、签名文件、真实 API Key 和本机绝对路径不应提交。没有 Key 的演示只能使用明确标注的预置草稿，不宣称是真实 AI 输出。

## 分支与提交

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定版本；当前包含初始工程，不表示业务完成 |
| `dev` | 集成与共同联调 |
| `feature/home` | 组长的契约与计划校验核心，沿用现有名称 |
| `feature/task` | 组员 1 的本地业务与数据模块 |
| `feature/record` | 组员 2 的模型接入与 AI 交互，沿用现有名称 |

从最新 `dev` 开发，经 PR 集成，不直接提交到 `main`。共享契约优先合入 `dev` 后再同步功能分支，不能仅凭远程分支存在就认为包含了最新工程。

提交示例：`feat: add plan validation`、`fix: prevent duplicate plan saves`、`test: cover invalid plan dates`、`docs: update module acceptance`。
