# StudyFlow 项目设计

## 1. 总体设计

StudyFlow 采用多页面结构，围绕学生学习任务管理进行设计。应用主要由首页仪表盘、任务管理、学习记录、资料推荐和个人中心组成。首页负责聚合展示学习状态，其他页面负责具体功能操作。

## 2. 页面结构

```text
首页 Dashboard
├─ 任务管理 Task
│  ├─ 任务列表
│  └─ 新增/编辑任务
├─ 学习记录 Record
│  ├─ 学习打卡
│  └─ 历史记录
├─ 资料推荐 Resource
└─ 个人中心 Profile
```

## 3. 数据模型设计

### 3.1 Task 学习任务

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 任务唯一标识 |
| title | string | 任务标题 |
| course | string | 所属课程 |
| priority | string | 优先级 |
| deadline | string | 截止时间 |
| completed | boolean | 是否完成 |
| createdAt | string | 创建时间 |

### 3.2 StudyRecord 学习记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 记录唯一标识 |
| date | string | 学习日期 |
| minutes | number | 学习时长 |
| note | string | 学习备注 |

### 3.3 Resource 推荐资料

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 资料唯一标识 |
| title | string | 资料标题 |
| type | string | 资料类型 |
| summary | string | 简介 |
| updatedAt | string | 更新时间 |

## 4. 技术设计

- 使用 ArkTS 编写业务逻辑和数据处理。
- 使用 ArkUI 的 Column、Row、List、Grid、Tabs、Button、Text、TextInput、Progress 等组件构建界面。
- 使用状态变量维护任务列表、学习记录和页面展示状态。
- 使用本地存储保存任务和学习记录。
- 使用模拟接口或远程 JSON 完成资料推荐模块的数据加载。

## 5. 页面设计要点

### 首页

首页采用卡片式信息分区，展示今日任务、完成率、学习时长和快捷入口。用户可以从首页快速进入主要功能页面。

### 任务管理页

任务管理页包含任务列表、筛选区域和新增按钮。任务项展示标题、课程、优先级、截止时间和完成状态。

### 学习记录页

学习记录页包含打卡按钮、学习时长输入和历史记录列表。用户可以查看近期学习情况。

### 资料推荐页

资料推荐页展示从接口获取的学习资料列表，并处理加载中、加载成功和加载失败状态。

### 个人中心页

个人中心页展示用户信息、应用设置和数据管理入口。

## 6. 开发流程

1. 组长建立 GitHub 仓库、初始化项目结构和文档。
2. 小组确认需求、页面流程和分工。
3. 每位成员在对应 `feature/*` 分支开发模块。
4. 功能完成后提交 Pull Request 到 `dev` 分支。
5. 组长进行合并、冲突处理和整体联调。
6. 完成功能测试、页面截图和测试报告。
7. 最终将稳定版本合并到 `main` 分支。
