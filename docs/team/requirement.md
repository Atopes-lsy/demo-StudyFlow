# StudyFlow 需求与验收

## 1. 目标与现状

开发 HarmonyOS AI 学习规划助手，帮助学生把学习目标转为可编辑、可校验、可保存的任务。当前工程仍为模板，以下均为待实现需求。

课程交付要求：

- 三人协作，使用多个组件实现至少两个能运行且较复杂的页面。
- 小组撰写 2000 字报告，说明分工、设计、测试和应用流程。
- 每人另外撰写 800 字感想，说明协作、问题及解决过程。
- 最后一周进行 5-10 分钟答辩，组长介绍总体，每人介绍自己的实际工作。

## 2. 首期需求

| ID | 需求 | 负责人 | 验收目标 |
| --- | --- | --- | --- |
| SF-01 | 任务管理 | 组员 1 | 新增、编辑、删除、完成、筛选可用，重启后恢复 |
| SF-02 | 首页与学习记录 | 组员 1 | 记录时长与备注，修改任务后首页统计一致 |
| SF-03 | 模型配置与密钥输入 | 组员 2 | 服务、Base URL、模型 ID、遮蔽 Key 可配置和清除 |
| SF-04 | AI 生成与草稿编辑 | 组员 2 | 主动发送目标和必要上下文，生成后可编辑、取消或确认 |
| SF-05 | 计划校验核心 | 组长 | 非法字段、日期、时长、预算或截止日违规被拦截 |
| SF-06 | 确认后保存 | 组员 1，组员 2 配合 | 未确认零写入，编辑后重新校验，重复确认不重复保存 |
| SF-07 | 网络与凭据边界 | 组员 2 | Key 不落盘、不进日志；失败不默认重试；过期响应不生效 |
| SF-08 | 设计、协作与证据 | 三人 | 有接口说明、Issue/PR、测试记录、截图和各自报告段落 |

### 首页、任务与记录

首页展示当天任务、完成情况和学习记录汇总；任务支持标题、课程、优先级、计划日期、截止日和预计时长。首期计划以天为单位，不实现小时级课表或最优排程。

任务和记录在本地保存，不因 AI 超时或没有 Key 而失效。异常输入和保存失败必须反馈，不显示虚假的成功。

### 模型设置与 AI 规划

模型入口位于 AI 规划页与设置页。首期验证一个模型服务，以及同格式兼容服务；不承诺全部模型接口、工具调用或 JSON 输出能力一致。

连接检查和生成测试分开，真实请求由用户主动触发并确认可能产生费用。Key 仅保留在当前进程，任务摘要只在用户确认后发给所选外部服务。详见[模型配置规格](model-configuration.md)。

### 校验规则

- 输出必须符合共同契约，不能把模型文本直接当作数据库记录。
- 草稿计划日期不能早于测试/请求时指定的当天，也不能超过目标截止日。
- 时长为正整数分钟；每日新草稿与当日已有未完成任务的预计时长总和不能超过用户预算。
- 缺少日期或时长的已有任务标记为上下文不完整，不能默认为零负担或宣称完全无冲突。
- 草稿修改后与最终保存前重新校验；上下文变化时使用最新任务快照。
- 无效草稿保留编辑机会，不自动触发付费修复请求。

## 3. 用户流程

1. 不配置模型也能手动创建任务、记录学习和查看首页。
2. 用户填写服务与 Key，检查连接并应用配置。
3. 输入学习目标、截止日和每日预算，确认发送必要任务摘要。
4. 生成草稿，展示校验结果；用户可修改或取消。
5. 确认时重新检查最新上下文，合法后批量保存，首页更新。
6. 学习后标记任务完成并记录时长，供下一次规划参考。

## 4. 可选与排除范围

MCP 最多先验证两个只读工具，基础闭环通过后单独批准；有协议实现、真实调用和测试证据后才标记完成。

首期不做资料推荐独立页面、复杂个人中心、账号云同步、AI 中转后端、模型训练、RAG、语音或永久保存 Key。新增功能不得挤占基础任务和校验测试。

## 5. 验收方法

用固定日期、假数据、网络测试替身验证业务边界，再在获得授权后验证真实模型。用例与结果见[测试报告](test-report.md)。构建通过不等于业务通过；未运行的用例一律保留“待测试”。
