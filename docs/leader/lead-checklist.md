# 组长工作步骤清单

本清单替代旧方案中由组长包办首页、存储、公共组件和全部测试的安排。组长的必做代码限定为共享契约、计划校验器及核心测试；其余按[三人分工](task-division.md)交给模块负责人。

## 0. 已观察到的基础条件

- [x] 当前目录已有 HarmonyOS `entry` 工程和首页模板。
- [x] GitHub 远程存在 main、dev 与三个功能分支。
- [x] 仓库已有文档、PR 模板和 `.gitignore`。
- [ ] 验证本机签名、SDK 同步、构建和 Phone 运行；由组员 1 执行并提供结果。
- [ ] 确认 `dev` 包含当前工程，而非只有旧文档。

仅勾选已核对的文件与分支存在性，不表示业务或环境已验收。

## 1. 先给团队最小契约

- [ ] 在 `feature/home` 定义 Task、StudyRecord、LearningContext、PlanDraft 和校验结果类型。
- [ ] 明确日期格式、预算单位、未知时长、草稿 ID、上下文版本和错误表示。
- [ ] 定义模型原始响应、校验入口及确认保存交接，不另做存储和 HTTP 层。
- [ ] 提供一份合法草稿和几份非法假数据，供组员并行开发。
- [ ] 最小契约先 PR 到 `dev`，通知两位组员同步。

## 2. 完成一个核心模块

- [ ] 实现原始响应解析与结构检查。
- [ ] 校验真实日历日期、必填字段、枚举和正整数时长。
- [ ] 校验目标截止日与每天的计划加已有任务预算。
- [ ] 缺少上下文时给出明确边界，不宣称全局无冲突。
- [ ] 返回可定位的字段错误，支持编辑后和保存前重新校验。
- [ ] 使用显式日期与假数据完成 PLAN-001 至 PLAN-012 核心测试。

不追加首页、公共 UI、导航、本地仓库、模型适配器、会话 Key 或整套后端；这些由两位组员按合同实现。

## 3. 只抓关键集成

- [ ] 请组员 1 证明本地恢复、统计同步、取消零写入和重复确认不重复保存。
- [ ] 请组员 2 证明 Key 不落盘、不进日志、地址变化清除、零自动重试和旧响应失效。
- [ ] 重点评审接口与校验调用，普通页面和文档由组员互审。
- [ ] 三人共同跑一条完整流程，缺陷回到对应模块负责人，不由组长全部接手。
- [ ] 收齐实际证据，未执行用例保留待测试。

## 4. 材料与答辩

- [ ] 自己写架构、计划校验和核心测试段落。
- [ ] 组员 1 汇总功能/流程和小组报告初稿；组员 2 汇总测试表、截图和演示材料。
- [ ] 核对小组 2000 字报告、每人 800 字感想和 5-10 分钟答辩要求。
- [ ] 每人只介绍实际贡献和实际遇到的问题。
- [ ] 审核是否有真实 Key、未验证指标或虚假完成状态。
- [ ] 验收后再提交稳定版本与作业材料，不默认发布应用市场。

## 5. 可选 MCP

- [ ] 基础闭环通过后再决定是否启用。
- [ ] 最多先验证读取任务与读取学习记录两个只读工具。
- [ ] 记录真实协议发现、调用及测试结果；本地函数不冒充 MCP。
- [ ] 端侧完整集成单独估算，不附加 RAG、模型训练或账号系统。
- [ ] 没有实现和证据时，在材料中标为可选或未完成。

## 工作量边界

每个 Issue 的负责人自己修复、测试、写报告；组长负责核心与关键决策。需求增加必须说明新增工作和被替换的范围，不能默认增加到组长名下。
