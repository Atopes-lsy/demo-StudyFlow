# StudyFlow 需求分析

## 1. 项目名称

StudyFlow - HarmonyOS 校园学习任务管理应用

## 2. 项目目标

本项目面向学生学习管理场景，开发一个能够记录学习任务、展示学习进度、保存学习记录并提供资料推荐的 HarmonyOS 应用。项目需要使用多个 ArkUI 组件，实现 2 个以上能够独立运行且功能较复杂的页面，并完成分工、设计、测试和应用流程说明。

## 3. 用户需求

目标用户为需要管理课程任务、作业截止时间和学习计划的学生。用户希望：

- 快速查看今天需要完成的学习任务。
- 添加、修改、删除学习任务。
- 标记任务是否完成，并查看整体完成进度。
- 记录每日学习打卡和学习时长。
- 查看学习资料、课程公告或推荐内容。
- 在应用关闭后仍然保留任务和记录数据。

## 4. 功能需求

### 4.1 首页仪表盘

- 展示今日任务数量。
- 展示已完成任务数量和完成率。
- 展示学习时长或打卡状态。
- 提供进入任务管理、学习记录、资料推荐等页面的入口。

### 4.2 任务管理

- 支持新增学习任务。
- 支持编辑任务名称、课程、优先级和截止时间。
- 支持删除任务。
- 支持切换任务完成状态。
- 支持按状态或优先级筛选任务。

### 4.3 学习记录

- 支持每日学习打卡。
- 支持记录学习时长。
- 支持展示历史学习记录。
- 支持根据记录更新首页统计数据。

### 4.4 资料推荐

- 通过模拟网络请求获取学习资料列表。
- 展示资料标题、简介、类型和更新时间。
- 网络加载失败时给出提示。

### 4.5 个人中心

- 展示用户昵称、学校或专业等基础信息。
- 支持主题、提醒或数据清理等简单设置项。
- 展示应用版本和项目说明。

## 5. 非功能需求

- 页面结构清晰，操作流程容易理解。
- 数据保存稳定，应用重启后任务和学习记录不丢失。
- 页面跳转流畅，组件显示完整。
- 代码结构清楚，便于 3 人协作开发。
- GitHub 提交记录清晰，能体现项目开发过程。

## 6. 应用流程

1. 用户进入首页，查看今日学习任务和完成进度。
2. 用户进入任务管理页，新增或修改学习任务。
3. 用户完成学习任务后，切换任务完成状态。
4. 用户进入学习记录页，进行学习打卡或记录学习时长。
5. 用户进入资料推荐页，查看课程资料或学习建议。
6. 用户进入个人中心，查看个人信息和应用设置。
