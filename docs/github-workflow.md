# GitHub 协作规范

## 1. 分支说明

| 分支 | 用途 |
| --- | --- |
| main | 最终稳定版本，用于提交作业和演示 |
| dev | 日常集成分支，所有功能先合并到这里 |
| feature/home | 首页、基础架构和数据模型 |
| feature/task | 任务管理模块 |
| feature/record | 学习记录、资料推荐和个人中心模块 |

## 2. 开发流程

1. 从 `dev` 分支创建自己的功能分支。
2. 在功能分支完成模块开发。
3. 本地运行并确认页面无明显错误。
4. 提交代码并推送到 GitHub。
5. 创建 Pull Request，请组长合并到 `dev`。
6. 组长完成整体联调后，将 `dev` 合并到 `main`。

## 3. Issue 建议

建议在 GitHub Issues 中创建以下任务：

- 项目需求分析与页面流程设计
- 首页仪表盘开发
- 任务管理模块开发
- 学习记录模块开发
- 资料推荐和个人中心模块开发
- 测试报告与答辩材料整理

## 4. Pull Request 模板

每次 Pull Request 建议说明：

```text

-

-
```
